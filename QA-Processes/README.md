# QA Processes

This section documents the QA workflows and standards I apply across projects: how defects are reported, reviewed, tracked and retested, and how regression testing is organized.

|---|---|

| [Bug-Report-Standards.md](Bug-Report-Standards.md) | Structure and writing rules for professional bug reports and improvement suggestions |
| [Bug-Report-Review-Process.md](Bug-Report-Review-Process.md) | How bug reports written by interns and students are reviewed and returned with feedback |
| [Regression-Testing-Process.md](Regression-Testing-Process.md) | When and how regression testing is planned and executed |
| [QA-Lead-Workflow.md](QA-Lead-Workflow.md) | Responsibilities and workflow when coordinating QA on a project |

## Where These Processes Are Applied

The project folders in this repository follow these standards. Examples:

- Full defect lifecycle with status, root cause and retest notes — `Web-Platform-Testing/Production Workflow and AI Workspace Platform/Bug-Reports/`
- Bugs and improvement suggestions in one consistent format — `Mobile-Testing/Healthcare Staffing Mobile Application/Bug-Reports/`
- Traceability from requirements to defects — the `RTM/` folder of each project

## Confidentiality

Process documentation contains no confidential employee data, client details or internal credentials.
